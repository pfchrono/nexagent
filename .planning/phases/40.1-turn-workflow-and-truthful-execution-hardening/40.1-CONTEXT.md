# Phase 40.1: Turn workflow and truthful execution hardening - Context

**Gathered:** 2026-04-27
**Status:** Ready for planning

## Phase Boundary

Phase 40.1 hardens turn execution truthfulness and operator controls in the runtime:
- explicit completion truth requires state-level confirmation
- long-run operations report blockers and verification state honestly
- status visibility becomes predictable and compact-first
- cancel/approval control paths become unambiguous

## Implementation Decisions

### Turn flow semantics
- **D-01:** Continue behavior stays active execution loop until done or blocked; `continue` does not mean one extra shot.
- **D-02:** `finish` during active execution performs graceful soft-stop and surfaces completed/in-progress/blocker details.
- **D-03:** Mid-loop block (approval, cancel, loop cap) stops immediately and returns blocker context.

### Completion signal and validation
- **D-04:** Completion is state-based only: provider done, no pending action, no queued work.
- **D-05:** Missing completion signal blocks `finish`; state marked unverified and shown as not done.

### Progress and truth labels
- **D-06:** Keep runtime action model unchanged; expose derived labels for UI/status only.
- **D-07:** `running` = active model/tool execution; `pending` = operator-gated/waiting.
- **D-08:** `finished` requires explicit execution success and no pending work.
- **D-09:** First transition signal appears in TUI footer statusline.

### Cancel and approval behavior
- **D-10:** `/cancel` triggers immediate cancel attempt and explicit canceled+blocker entry.
- **D-11:** Approval needed path shows blocked state and explicit "awaiting approval" summary.
- **D-12:** `finish` while approval pending pauses and keeps request alive.
- **D-13:** Missing `/approval` after clear prompt repeats once and waits.

### Failure and stop conditions
- **D-14:** Empty provider exit with status 0 counts as failure-to-respond.
- **D-15:** Empty responses are unverified until explicit completion summary exists.
- **D-16:** Provider/auth/model/transport failures map to blocked external dependency with action summary.

### Long-turn visibility defaults
- **D-17:** Compact /status defaults minimal fields: state, phase, objective.
- **D-18:** Long-turn trace defaults compact; full detail shown on explicit request.
- **D-19:** Compact /status includes blocker reason inline.
- **D-20:** Transcript prioritizes blockers/errors first, then state transitions.
