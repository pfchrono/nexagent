<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Raw user prompt/command -> runtime control | `/approval`, `/cancel`, `/continue`, `/finish` can alter execution state |
| Provider transport / process output -> session state | Transport exit/result may falsely appear complete |
| Session state -> status/transcript rendering | UI-level labels can mislead if derived from non-truthful signals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40.1-01 | S | `src/provider.ts` exit handling | mitigate | map `exitCode===0` + empty output to explicit failure state with blocker/failure event |
| T-40.1-02 | T | `src/cli.ts` `/finish`/`/continue` command handling | mitigate | block completion without proof and surface explicit recovery state |
| T-40.1-03 | I | `src/cli.ts` status and transcript renderers | mitigate | derive labels from session proof, include inline blocker in compact status |
| T-40.1-04 | D | `src/provider.ts`/`src/cli.ts` loop interruption | mitigate | keep cancel/approval state and operation details in event log and status output |
</threat_model>
