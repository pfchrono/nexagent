# Phase 48.1: dual-mouse-interaction-mode - Research

**Researched:** 2026-04-27  
**Domain:** terminal mouse interaction multiplexing (wheel scroll + drag-select copy), persistence, and capability fallback in current TUI runtime.  
**Confidence:** MEDIUM

<user_constraints>
## User Constraints (from 48.1-CONTEXT.md)

- Hybrid mode required: auto behavior + manual override.
- Supported modes: `scroll`, `select`, `auto`.
- Startup default uses last persisted mode from workspace state.
- Expose both command and keybind controls.
- Copy feedback must appear in statusline and command-boundary event output.
- Capability conflict must degrade gracefully with warning + fix hint.
- Persist mode in `.nexagent/session.json` only (workspace scope).

</user_constraints>

<phase_requirements>
## Phase Requirements (from ROADMAP.md)

1. Mouse-wheel scroll works in transcript pane again.
2. Drag-highlight + clipboard copy still works without disabling scroll.
3. Startup/reload behavior is deterministic and surfaced in status/help text.
4. Capability conflicts provide explicit fallback mode + user-visible notice.

</phase_requirements>

## Existing Code Surface

### Primary integration files
- `src/cli.ts` — TTY event loop, raw mode input parsing, scroll offset state, copy status UI hints.
- `src/runtime/persistence.ts` — persisted workspace session state (`.nexagent/session.json`).
- `src/runtime/session.ts` — runtime/session state carrier for mode flags and current interaction status.

### Observed design constraints
- Current runtime heavily centralizes TTY behavior in `src/cli.ts`, so phase should be additive there.
- Persistence already best-effort; mouse mode should follow same non-fatal write/read behavior.
- Command toggles already patterned for other modes (`/statusline`, `/caveman-mode`) and can be mirrored.

## Recommended Implementation Shape

1. Add mouse-mode state contract (`auto` | `scroll` | `select`) to session + persistence.
2. Add command handler `/mouse mode <scroll|select|auto>` plus status output.
3. Add keyboard toggle shortcut (single deterministic key chord) cycling modes.
4. Gate mouse event handling by active mode:
   - `scroll`: capture wheel events for transcript offset.
   - `select`: release capture path to allow native terminal drag-select.
   - `auto`: choose preferred path from capability probe; fallback to `select` with warning.
5. Emit explicit notices:
   - capability probe result
   - fallback cause
   - copy feedback event line + statusline chip
6. Ensure `/reload` reapplies persisted mode and emits mode restore activity.

## Donor Parity Guidance

- Use `~/code/codex-fresh` and `~/code/free-code` as reference for:
  - compact status notices
  - deterministic interaction mode indicators
  - non-noisy copy/selection feedback
- Borrow behavior shape only; keep `nexagent` command contracts and event naming local.

## Risks / Pitfalls

- Wheel capture can break selection depending terminal + raw-mode interplay.
- Overly aggressive fallback warnings can spam transcript if emitted per frame.
- Mode state drift between in-memory and persisted state during `/reload`.

## Validation Strategy

- Manual checks in one runtime session:
  - start in persisted mode
  - switch modes via command and keybind
  - verify wheel scroll in `scroll` mode
  - verify drag-select copy in `select` mode
  - verify `auto` picks capability path and emits warning on conflict
  - run `/reload`; verify mode restore and deterministic status text
