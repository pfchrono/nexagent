# Phase 48.1: dual-mouse-interaction-mode - Context

**Gathered:** 2026-04-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Restore mouse-wheel transcript scrolling while preserving drag-highlight copy behavior in terminal sessions, with deterministic startup/reload behavior and explicit fallback signaling.

</domain>

<decisions>
## Implementation Decisions

### Mouse mode architecture
- **D-01:** Use hybrid architecture: automatic capability behavior with manual override.
- **D-02:** Runtime supports explicit modes (`scroll`, `select`, `auto`) even when auto-detection is active.

### Startup behavior
- **D-03:** Default mode at startup is last persisted mode.
- **D-04:** Reload path must retain and reapply persisted mode deterministically.

### Controls and routing
- **D-05:** Expose both command and keybind controls for mouse mode changes.
- **D-06:** Command surface uses explicit mode command (`/mouse mode <scroll|select|auto>` equivalent contract).

### Copy feedback
- **D-07:** Copy feedback appears in statusline and command-boundary event output.
- **D-08:** Feedback must remain concise and non-noisy.

### Conflict/fallback policy
- **D-09:** On terminal capability conflict, degrade gracefully with warning and suggested fix.
- **D-10:** Do not hard-fail interaction loop when capability mismatch occurs.

### Persistence scope
- **D-11:** Persist mouse mode per-workspace in `.nexagent/session.json`.
- **D-12:** No global home-level persistence in this phase.

### the agent's Discretion
- Exact keybind assignment for mouse-mode toggle.
- Exact warning message copy as long as it includes cause + fix hint.
- Exact event formatting for copy feedback and capability warnings.

</decisions>

<specifics>
## Specific Ideas

- Keep both wheel scroll and drag copy available without forcing single hard mode.
- Operator should always see current mode and fallback reason when capability mismatch occurs.
- Startup/reload behavior should feel stable: mode should not randomly change.

</specifics>
