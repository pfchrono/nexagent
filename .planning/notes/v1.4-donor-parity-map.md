# v1.4 Donor Parity Map

Goal: stop treating donor parity gaps as vague polish debt. Turn them into concrete scope.

## Biggest current gaps

### Runtime behavior truth

- Model still claims work done before tool/action verification.
- Model still pauses after partial progress when user intent says continue until done or blocked.
- Turn-progress state too coarse compared with donor harnesses.
- Prompt/system instructions still too weak on:
  - act before narrate
  - continue until done
  - exact transcript/file output vs summary
  - do not fake implementation/testing

### TUI interaction

- Middle transcript pane still needs reliable scroll behavior.
- Mouse-wheel transcript scroll still rough.
- Copy/select interaction not implemented yet.
- Trace blocks need real expand/collapse interaction, not only coarse toggle.
- History picker and model picker exist, but still plain.
- Footer/HUD still lighter than donor quality bar.

### Command and workflow surface

- Command families still uneven and partly discoverable only through slash memory.
- `/model` exists, but chooser UX still basic.
- `/skill` or `$skill` workflow missing.
- Progress/continue workflow semantics still weak.

### Missing scoped systems promoted from old out-of-scope notes

- Hook execution engine
- Plugin install/marketplace workflow
- Command-family spec system
- Stronger skill system
- Stronger prompt foundation follow-through
- Provider-native tool/function parity follow-through
- `--yolo` guarded mode
- Clipboard image paste / multimodal attachments
- Framework evaluation spike for TUI rewrite path if hand-rolled renderer keeps fighting us

## Donor takeaways worth importing

### `free-code`

- Ink-based TUI structure reduces manual layout pain.
- Stronger prompt-section architecture.
- Project-scoped history and picker workflow.
- Better command/system surfaces (`/model`, `/skills`, statusline).
- Better "keep going" operator feel from query loop and command system.

### `hermes-agent`

- Best current operator-facing turn-progress display.
- Better tool trace grouping and turn-stage visibility.
- Better home/start panel and bottom HUD rhythm.
- Better transcript flow with action visibility during long turns.

### `codex-fresh`

- Better event/phase vocabulary for long-running turns.
- Better structured transport/progress event model.
- Better approval/config shape references.

### `opencode`

- Strong TUI framework candidate if current renderer keeps fighting feature work.
- Better scroll/session architecture worth evaluating.

### `openrouter-create-agent` / `openrouter-create-agent-tui`

- Runtime owns truth; TUI renders runtime.
- Typed event model should drive transcript, progress, tools, approvals.
- Split renderer/input/runtime before more major UI work.

## Recommended scope promotions

### Promote into active `v1.4`

1. Turn workflow and truthful execution hardening
- continue-until-done semantics
- no fake implementation/testing claims
- better progress state during long turns

2. Transcript interaction polish
- reliable `PgUp/PgDn`
- mouse-wheel scroll
- transcript selection/copy
- copied char count feedback

3. Picker and trace interaction polish
- richer history popup
- richer `/model` chooser
- expandable trace/tool blocks

### Promote into next milestone

1. Skill system foundation
- `/skill`
- `$skill`
- provider/runtime prompt injection path for active skills

2. Prompt/system foundation follow-through
- stronger exactness/execution guidance
- donor-style modular prompt sections
- better dynamic/stable prompt boundaries

3. Command and workflow parity
- command-family spec system
- better slash autocomplete/discoverability
- stronger continue/resume workflow behavior

4. TUI framework evaluation
- compare current renderer vs Ink vs OpenTUI/opencode-style path
- decide whether to keep patching or rewrite renderer shell

5. Parked capability promotion
- `--yolo`
- clipboard image paste
- hook execution engine
- plugin workflow

## Recommendation

Do not treat remaining issues as "just polish".

Need two tracks:

- finish `v1.4` interaction/runtime honesty work
- immediately draft next milestone for skill system, prompt hardening, workflow parity, and framework decision
