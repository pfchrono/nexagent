# Roadmap: nexagent v1.2

Source: promoted from `.planning/NEXT-MILESTONE.md`.

## Overview

`v1.2` moves `nexagent` from truthful readonly harness into practical writable coding agent with stronger runtime contracts, safer mutation surfaces, and harder operational guarantees.

## Phases

- [x] **Phase 20: Runtime hardening and verification sweep** - Run full hardening sweep, clean rough edges, and lock honest verification paths before writable powers expand.
- [x] **Phase 21: Provider-native tool calling** - Replace XML shim where supported with provider-native structured tool calling while preserving one shared tool registry.
- [x] **Phase 22: Writable file and patch tools** - Add guarded internal write and patch tools under same repo-local policy layer.
- [x] **Phase 23: Guarded shell execution** - Add model-callable shell tool with explicit risk classes, output caps, and destructive-command blocking.
- [x] **Phase 24: Archivist save and checkpoint flow** - Add bounded memory save/checkpoint actions with visible read-vs-write lineage.
- [x] **Phase 25: Human approval and operation controls** - Add approval gates, better risky-operation visibility, and stronger interrupt/cancel/steer controls.

## Phase Details

### Phase 20: Runtime hardening and verification sweep
**Goal**: stabilize `v1.1` runtime before writable agent powers land.
**Depends on**: Nothing
**Success Criteria** (what must be TRUE):
  1. Full automated verification sweep runs cleanly.
  2. Build and compile paths stay honest after artifacts exist.
  3. Any hardening fixes stay small and directly tied to verification truth.
**Plans**: `20-01`

### Phase 21: Provider-native tool calling
**Goal**: replace harness XML tool-call shim with provider-native structured tool calling where current transports support it.
**Depends on**: Phase 20
**Success Criteria** (what must be TRUE):
  1. Structured provider-native tool calling exists on supported transports.
  2. Shared internal tool registry remains single source of truth.
  3. Unsupported transports degrade honestly without pretending parity.
**Plans**: `21-01`

### Phase 22: Writable file and patch tools
**Goal**: add guarded writable coding tools for practical code changes.
**Depends on**: Phase 21
**Success Criteria** (what must be TRUE):
  1. Internal `write_file` and `apply_patch` style tools exist.
  2. Writable tools reuse existing repo-local policy boundaries.
  3. Dangerous destinations remain blocked and visible.
**Plans**: `22-01`

### Phase 23: Guarded shell execution
**Goal**: add model-callable shell execution with explicit safety boundaries.
**Depends on**: Phase 22
**Success Criteria** (what must be TRUE):
  1. Shell tool is model-callable under repo-pinned cwd.
  2. Output caps and destructive-command blocking are enforced.
  3. Risk class and activity stay visible in runtime surfaces.
**Plans**: `23-01`

### Phase 24: Archivist save and checkpoint flow
**Goal**: extend current retrieval-only Archivist path with explicit bounded writes and checkpoints.
**Depends on**: Phase 23
**Success Criteria** (what must be TRUE):
  1. Memory save/checkpoint actions are explicit and inspectable.
  2. Retrieval and write lineage remain separately visible.
  3. Persisted session summaries stay bounded.
**Plans**: `24-01`

### Phase 25: Human approval and operation controls
**Goal**: improve operator control around risky and long-running writable actions.
**Depends on**: Phase 24
**Success Criteria** (what must be TRUE):
  1. Risky operations can require explicit approval state.
  2. TUI/status surfaces show pending risky action clearly.
  3. Interrupt/cancel/steer behavior is stronger around tool turns.
**Plans**: `25-01`
