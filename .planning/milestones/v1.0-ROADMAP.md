# Roadmap: nexagent

Source: imported from `Plan.md`.

## Overview

`nexagent` ships in honest buildable slices: keep baseline truthful, harden shared runtime, prove interface consumers against that runtime, then widen instruction assembly, provider transport, tools, automation, memory, and command surface without letting donor behavior redefine product identity.

## Phases

- [x] **Phase 0: Keep baseline honest** - Preserve runnable baseline without fake parity or marketing drift.
- [x] **Phase 1: Stabilize shared runtime core** - Harden one canonical runtime truth model for every interface.
- [x] **Phase 2: Harden first real TUI** - Turn terminal prototype into dependable runtime visibility.
- [x] **Phase 3: Harden GUI shell** - Make GUI consume shared runtime contracts after TUI proves them.
- [x] **Phase 4: Deepen prompt and instruction assembly** - Turn layered prompt output into explicit inspectable subsystem.
- [x] **Phase 5: Deepen provider transport** - Move narrow provider execution toward transport trustworthy enough to use.
- [x] **Phase 6: Expand tool execution surface** - Make harness feel like harness, not provider wrapper.
- [x] **Phase 7: Add hooks, plugins, and repo-local automation** - Open controlled repo-specific workflow behavior.
- [x] **Phase 8: Add memory and persisted harness state** - Add persistence only after core runtime, transport, instructions, and tools are stable.
- [x] **Phase 9: Evolve command surface and workflow affordances** - Expand narrow baseline into harness-native operations.

  2. Current runtime surface stays runnable.
  3. Missing subsystems remain labeled missing.
  4. Compatibility language stays constrained.

### Phase 1: Stabilize shared runtime core
**Goal**: Harden one runtime truth model for every interface.
**Depends on**: Phase 0
**Success Criteria** (what must be TRUE):
  1. Shared runtime owns config, session, provider, MCP, repo context, and progress truth.
  2. CLI remains truthful bootstrap/debug surface.
  3. Interfaces do not fork runtime state.
**Plans**: 1 plan

Plans:
- [x] 01-01: Centralize provider selection and action/progress updates in shared runtime session helpers so reload and command flows do not fork runtime truth.

### Phase 4: Deepen prompt and instruction assembly
**Goal**: Turn layered prompt output into a real subsystem.

### Phase 5: Deepen provider transport
**Goal**: Move from narrow provider execution into transport that is real enough to trust.
**Depends on**: Phase 4
**Success Criteria** (what must be TRUE):

  3. Routing semantics for new providers require spec coverage before implementation.

### Phase 6: Expand tool execution surface
**Goal**: Make harness feel like harness, not provider wrapper.

**Success Criteria** (what must be TRUE):

  2. Tool contracts are usable across interfaces.
  3. Search/edit/tool ergonomics are treated as core behavior.
**Plans**: 1 plan

Plans:

**Depends on**: Phase 6
**Success Criteria** (what must be TRUE):
  1. Hook execution is explicit and inspectable.
